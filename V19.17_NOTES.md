# TYSHI ZONE v19.17 (built on the real 19.15)

Built part by part. This file lists what each finished part changed.

## Part A: Universal Servers are the main links  (DONE)

**What changed**
- New admin section **Universal Servers** (first section in the admin menu and on the Overview page).
  Any number of servers (not limited to 3), each with: name, on/off, AniList or TMDB ID, a SUB link and a DUB link.
  Placeholders: `{anilistId}` `{tmdbId}` `{season}` `{episode}`. It has a **Save** button and a **Test** area.
- Settings are saved in ONE Firebase document: `siteConfig/universalServers` (no Firestore rules change needed).
- Every anime now plays through the Universal Servers, even ones never added in the admin panel.
  The episode list comes from AniList (finished = full total, airing = episodes aired so far).
  Nothing is saved per episode.
- A link saved by hand for an episode still works and wins over the universal link.
- A server whose needed ID can't be found (for example no TMDB match) is hidden for that anime.
- DUB: if a server has a DUB link, DUB is offered for every episode and plays from it. Nothing is guessed from AniList.
  (If a server has no DUB link, that server plays SUB.) The DUB option is greyed out only when no server has a DUB link.
- TMDB servers: the site guesses the TMDB series by title (only a confident guess is used). On each anime's own admin page
  you can **Confirm** the match once, search for another, or mark "no match". Your choice is saved in `siteConfig/universalTmdb`.
- **Watch Now** always opens the player. The anime request dialog is gone from the site and the **Requests** section is gone
  from the admin panel (the Firebase data is untouched).
- "Manage episodes" buttons and the old Manage episodes page are gone (that address now redirects to the details page).
  The admin-only "Admin" button on a details page stays (only a signed-in admin sees it).
- The watch page no longer shows the yellow database warning or any "not added" / Firebase wording.
  An anime with no episodes out yet shows a plain "Nothing to watch yet" message.
- Details page: shows the episode count from AniList ("Movie" for movies, nothing when AniList has no number).
  The Episodes row shows the first 40 episodes with a "Show more" button so long shows stay fast.
- Continue Watching keeps working for episodes played through a universal link.
- Old **Servers** and **Bulk import** still work. They moved to the end of the admin menu.

**New files:** `src/lib/universal-servers.ts`, `src/components/admin/universal-servers-view.tsx`,
`src/components/admin/universal-anime-panel.tsx`

**How to test**
1. Admin > Universal Servers: paste a SUB link (and DUB link) with `{anilistId}` and `{episode}`, switch it on, Save.
   Use the Test area (AniList ID 21, episode 1) to see the links.
2. Open an anime you NEVER added (for example from Search). It should open and play right away.
3. Watch Now should never ask you to request anything. No yellow warning on the watch page.
4. Open an anime in the admin panel (Episodes). The "Universal Servers" box shows how many episodes are available.
   If you use a TMDB-type server, confirm the TMDB match there.

## Changes after the first test of Part A  (DONE)

- **Server menu:** the "SUB fallback" text is gone. The menu shows only the server names.
- **DUB always works from the universal link.** The old "DUB must be known" rule is removed.
- **Placeholders:** use `{id}` (the anime's ID: AniList ID, or TMDB ID on a TMDB server), `{ep}` (episode) and `{season}`.
  The old names `{anilistId}`, `{tmdbId}`, `{episode}` still work. Upper/lower case, spaces, `{{id}}`, `${id}` and `[id]` are all accepted.
- **Any link the player can open works:** a normal link, a link without `https://`, a direct video file, or a whole pasted
  `<iframe ...>` code. The builder now uses the same reader as the player.
  (Direct `.m3u8` streams are not supported by the player itself, so they are not either.)
- **Auto-play next episode:** now also in **Settings > Player** (it was only in the watch page's ⋮ menu). It is on by default.
  It works when the player tells the page the video ended. The page now understands many more "ended" messages
  (wrapped messages like `{type:"PLAYER_EVENT", data:{event:"ended"}}`, plain "ended", players that moved to another address,
  and "time is at the very end of a real episode"). Ad events never count. Players that never send anything can't be detected
  from outside, so for those use the Next button.
